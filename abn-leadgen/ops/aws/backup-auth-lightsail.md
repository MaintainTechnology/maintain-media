# Backup identity on the current Lightsail host

The current host is Lightsail. Its general IAM service documentation says it does not support service roles; the documented EC2 instance-profile mechanism must not be assumed to exist here. The Lightsail service-linked role is used by the service for snapshot export and account public-access checks, not as a general S3 identity for our backup process. [Lightsail IAM support](https://docs.aws.amazon.com/lightsail/latest/userguide/security_iam_service-with-iam.html), [service-linked role permissions](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-using-service-linked-roles.html).

Lightsail's credential-free resource attachment is specifically for a **Lightsail bucket in the same region** and grants full bucket access. It is not a documented way to attach an arbitrary S3 IAM role to the existing instance. Switching to Lightsail Object Storage would be a different storage/cost/permission contract and would need compatibility checks for our S3 configuration reads and lifecycle policy. [Official resource-access procedure](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-configuring-bucket-resource-access.html).

For this single host with no established certificate infrastructure, the smallest supported setup is one dedicated non-console IAM user with one programmatic key, restricted to the approved backup bucket and deployment prefix. Install it directly into private service-owned credential storage through the authorized provisioning connection; do not put it in chat, Git, a backup, logs, or the interactive administrator profile. Record a key rotation/revocation owner and test its removal. IAM itself has no extra charge; S3 storage/requests retain the proposed backup budget. This is a pragmatic minimal setup, with a long-lived credential that needs management. [Official CLI credential setup on Lightsail](https://docs.aws.amazon.com/lightsail/latest/userguide/lightsail-how-to-set-up-and-configure-aws-cli.html), [IAM cost](https://docs.aws.amazon.com/IAM/latest/UserGuide/introduction.html).

The required IAM actions are `s3:GetBucketLocation`, `s3:GetBucketPublicAccessBlock`, `s3:GetBucketPolicyStatus`, `s3:GetBucketVersioning`, and `s3:GetLifecycleConfiguration` on the one bucket; `s3:ListBucket` constrained by the exact deployment prefix; and `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` only under `abn-backup/<deployment-id>/`. No bucket creation, lifecycle/policy writes, public ACL changes, IAM administration, account-wide bucket listing or other application objects are needed. Keep TLS mandatory. The adapter independently verifies the expected account, region, privacy, lifecycle, immutable UUID keys and encrypted readback.

A stronger alternative is IAM Roles Anywhere: a separate CA/trust anchor, workload certificate/private key, scoped role/profile, and the official credential helper configured as AWS CLI `credential_process`. The helper obtains renewable temporary credentials without a stored IAM access key. Applying this generic certificate-authenticated process to Lightsail is an implementation inference from the documented helper, not a tested deployment here. It requires certificate custody, expiry, rotation and revocation verification. Roles Anywhere has no additional service charge; a self-managed CA avoids AWS Private CA fees. Do not provision paid AWS Private CA merely for this host. [Credential helper](https://docs.aws.amazon.com/rolesanywhere/latest/userguide/credential-helper.html), [trust requirements](https://docs.aws.amazon.com/rolesanywhere/latest/userguide/trust-model.html), [AWS's no-additional-cost statement](https://aws.amazon.com/about-aws/whats-new/2023/09/iam-roles-anywhere-govcloud-regions/).

No unattended identity, bucket, live backup or workload certificate was created while preparing this note. The existing interactive CLI approval only bootstraps infrastructure. The current retention/backup authority is closed, so an identity alone would still not permit data copying. Production backup acceptance requires actual authority, installed identity, Sydney provider verification, upload/readback, expiry and quarantine-restore evidence.
