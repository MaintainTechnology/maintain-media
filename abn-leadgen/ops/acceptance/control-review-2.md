# Control/API integration review 2

8 September 2026. Read-only review of the runnable control/API and integration wiring against specification v4.0, after review-1 fixes and before the next build pass. No numerical quality score is assigned. Parent-owned pipeline, retention, keys and control files were not modified by this reviewer. Line locations describe this review snapshot and may shift during the concurrent build.

## Actionable findings

1. **P1 — Operator assignment does not fence phone intents (R24/R26).** `control/api.py:128–139` has an assignment helper and applies it to candidate checks, worklist reads and outcome writes. `POST /v1/action-intents` at lines 173–179 and consumption at 181–189 do not call it. An operator denied the candidate-check route for an unassigned contact can still submit known lead/contact IDs through the phone intent path; `Service.action/consume` knows actor ID, not assignment. Require assigned contact/worklist access at both creation and consumption for operator callers, including assignment revocation between those steps. Certified sender scope remains a separate service authority. Test an unassigned operator plus assigned positive case against the actual API/database.

2. **P2 — Activity lead identity is not bound to the assigned worklist (R26/R32/R34).** The activity handler checks only `d['worklist_id']` assignment before inserting the independently supplied `lead_id`. An operator assigned worklist A can attach an activity to a known lead from worklist B. Validate that a supplied lead is a row of the supplied authorised worklist. Correction insertion also only checks same actor; multiple corrections of the same original are accepted although `union_work_seconds` rejects branched correction history. Add a unique current-correction constraint or deterministic append-only supersession contract and test API acceptance against the metrics reader.

3. **P1 — Reviewed business-group merge remains absent (R13/T016/R25).** `qualify/identity.py` is absent, no merge endpoint/service is registered, and searches for `merged_into_group_id` find schema storage and restore only. Existing alias matching detects more than one group and raises `IDENTITY_MERGE_REVIEW_REQUIRED`, but offers no reviewed resolution path. Distinct groups cannot be deliberately merged while propagating all suppression before export. Implement a reviewer-authorised, audited, version-bound merge under canonical locks: reconcile source aliases, future token matching, worklist/CRM dedupe and restriction union. Same-name/shared-endpoint evidence alone must never authorise it. Prove both restricted-to-unrestricted merge directions and subsequent incoming alias matching.

4. **P1 — The produced CSV cannot initialise the supplied Sheets bridge (R31/R32).** `export.report.safe_rows` emits `contact` and review labels but omits the bridge's required editable/status columns: `status`, `attempts`, `invitation_state`, `invitation_evidence_ref`, `notes`, `occurred_at`, `save_state`. It also omits schema-required `generated_at`, `safe_contact_view` and `opener`. `sheets_bridge.gs.headers_` therefore throws immediately when used with the generated `worklist.csv`. Use one explicit CSV/schema contract, hydrate current outcome/version state instead of resetting existing outcomes, and test a real generated CSV through the bridge header/protection/edit path. Root assigned this correction to the output builder after the finding was recorded; that fix is not an independent review pass.

5. **P2 — Operational and cohort helpers are not wired into a runnable report (R34/R35/R38/T050/T054).** Repository searches find `cohort_metrics`, `union_work_seconds` and `evaluate_alarms` only in their definitions and unit tests. The current pipeline returns selected/blocked counts and ad-hoc source error alarms; it does not read dated outcome/activity history into cohort denominators, report missing cost categories, or evaluate/durably deduplicate the complete alarm inventory. Unit coverage of pure helpers is useful but does not prove an operator's actual run reports these values. Add a database-to-metrics projection and an immutable summary/artifact with cohort window/sample sizes, and persist alarm outbox uniqueness before mock delivery. Keep unmeasured pilot values explicitly missing.

6. **P2 — Source-date and outcome projection are missing from report context (R31/R34).** `export/worklist.py:report_context` does not pass `source_published_at`, current outcome, attempts, invitation, notes or activity date to `ReportRow`. All source ages render unknown even where an accepted source manifest contains a verified publication date, and a re-export cannot show current operator outcomes. Unknown QBCC publisher metadata must remain unknown; do not substitute retrieval time. Join only source-owned evidence and current outcome projection, preserve the selected originating signal/tier and expose actual known dates with their meaning.

7. **P2 — Typed CRM mapping remains a passive file (R33/T049).** `integrations/crm_fields.yaml` is referenced by its structural unit test, but the actual CRM projection builds its own field dictionary and never loads/validates the configured custom-field IDs/types or all required internal field mappings. Live mode correctly remains disabled; the missing integration is still an offline contract gap. Use the fixture mapping to validate approved projection types/nullable fields and custom IDs at the provider boundary; add an actual mapping contract test. Live field IDs/countries/vendor behaviour remain a separately pending G5 gate.
