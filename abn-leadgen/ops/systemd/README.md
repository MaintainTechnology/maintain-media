# Single scheduler deployment templates

These units are uninstalled fixture-default templates, not deployment evidence. Use systemd only; do not add duplicate cron jobs. Both source services share `/run/abr-engine/pipeline.lock`; flock returns code 4 on overlap and releases the process lock after a crash. Database stage/source locks and recorded heartbeat recovery are still required inside the CLI. A successful process lock does not grant production access.

Before installation, configure the documented CLI paths, private writable artifact root under `/var/lib/abr-engine`, credential loading from the selected secret manager, dedicated account, database access and approved capability records. Verify actual CLI flags and configuration in the target revision. Changing a mode environment variable alone must not enable production. The templates intentionally contain no secrets or live provider configuration.

Run `systemd-analyze verify` on the host, exercise simultaneous starts/crash recovery, and capture service/timer status, missed-heartbeat alarms and restart receipts. That Linux host drill is pending. The 2 GiB cgroup bound covers each service; DuckDB buffer configuration is only 512 MiB and is not the same as an RSS limit. Size spill/disk with the capacity admission worksheet before a large run. Set and test host-level public-only crawler egress; address-family restrictions alone do not block private destination IPs.

ABR discovery runs every six hours UTC; QBCC runs weekly Monday UTC. Persistent timers catch up after downtime. They invoke the same operator CLI and depend on its immutable manifests and alarms. Operations notifications remain disabled until configured release approval. Enabling a timer requires G3/G7 evidence, an audited runbook drill and a current release configuration.

`abr-engine-monitor.timer` checks every minute using `alarms check --mode fixture`, then `alarms drain --mode fixture`. This uses the same systemd scheduler; it never sends notifications. The monitor reports active database runs without a heartbeat for over300 seconds and leaves external expected-run inventory unknown unless an evidence observation supplies its timestamp/interval. Concurrent mock drains use database leases and deduplicated mock receipts. These templates remain uninstalled; no Linux timing or service-account access claim is implied by the Windows CLI tests.
